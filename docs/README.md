## 문서 버전 관리

1. 평소 수정은 현재 문서에서 진행한다. 같은 정책을 여러 문서가 다루면 관련 요구사항 ID, 로드맵 후보, 검증 절차를 함께 확인한다.
2. 합의나 단계 검토를 마쳐 문서 묶음을 확정하면, 그 시점의 여섯 문서를 다음 버전 폴더에 보관한다. 폴더 안의 문서 링크가 같은 버전을 가리키는지 확인한다. 예를 들어 다음 묶음은 `versions/v0.3/`에 둔다.
3. [문서 변경 이력](CHANGELOG.md)에 확정 날짜, 기준 커밋, 변경 이유와 영향을 받은 문서를 기록하고 이 목록의 최신 버전을 갱신한다. 확정된 폴더의 본문은 그대로 보존한다.

문서 묶음의 **v0.1·v0.2**는 제품 로드맵의 **V0~V4** 및 개발 단계 **M0~M6**과 독립이다. 오탈자나 초안 수정은 현재 문서의 Git 이력으로 추적한다.
