## 문서 버전 관리

- **제품 V0~V4**, **개발 단계 M0~M6**, **문서 v1.0·v1.1**은 서로 독립이다. 인수 시나리오의 `V-01` 같은 ID도 제품 버전과 별개다.
- 문서 경로는 유지한다. 개정 이력에는 날짜, 바뀐 문서와 번호, 변경 이유, 관련 요구사항·기능·검증 ID를 남긴다. 이전 전문은 Git 이력에서 조회한다.
- 초안이나 첫 발행에는 v1.0을 사용한다. 기존 합의의 설명, 구현 기본값, 후보 순서, 확인 절차를 수정하면 소수점 아래 번호를 올린다. 사용자에게 약속한 출시 범위나 핵심 정책을 바꿔 기존 개정과 호환되지 않으면 검토 후 앞자리를 올린다.
- **같은 제품 결정을 여러 문서가 다루면 하나의 변경으로 대조한다.** 로드맵의 범위·우선순위가 바뀔 때는 제품 기획서의 약속과 출범 계획의 검증 조건을 확인한다. 구현 중 발견한 제약이 우선순위에 영향을 주면 그 근거를 로드맵에도 반영한다. 영향을 받는 UX와 테스트를 같은 변경에서 수정한다.
- V2 이후 후보의 배치는 제안 상태로 유지하고, 착수 결정이 생기면 근거와 승인 상태를 함께 기록한다. 최종 합의가 필요한 정책 충돌은 변경 후보로 표시한다. 기존 약속을 먼저 유지하고 미결 사항을 문서에 남긴다.
