## 1. 제품 제안

**Me-mento는 같은 공부를 한 사람의 노트에서 놓친 내용을 발견하고, 그 노트를 iPad에 복사해 자기 설명으로 다시 공부하는 암기노트 앱이다.**

자격증 공부를 하다 보면 교재나 공유 PDF에서 시험에 나오지 않을 것 같은 문제를 건너뛴 뒤, 다른 수험생이나 합격자도 같은 판단을 했는지 궁금해진다. 현재는 구글과 블로그에서 찾아보거나 주변에서 공유받은 필기본·워드 파일을 훑는다. 참고할 내용을 찾고 나면 그 자료 위에 내 손글씨를 덧붙이고, 원래 설명을 읽으면서 자기 사례나 이야기로 풀어 쓰고, 흩어진 개념을 다시 연결하는 작업이 남는다.

공개 노트에서 발견할 수 있는 것은 **다른 사람이 챙겨 적은 내용**이다. 내용이 빠진 이유는 공개 노트만으로 알기 어렵다. 출제 경험은 소개에 자발적으로 남길 수 있다. 저자가 별도 목차, 출제 여부, 합격 인증을 제출하는 절차는 첫 범위에서 제외한다.

### 첫 고객과 사용 장면

| 사용자 | 상황 | Me-mento에서 얻는 결과 |
|---|---|---|
| 정보처리기사 수험생 | 공부 범위를 정리하다가 다른 사람의 노트에서 처음 보는 내용을 발견한다. | 공개 노트를 읽고, 필요하면 즐겨찾기에 저장하거나 전체를 가져와 다시 공부한다. |
| 자신의 노트를 만드는 학습자 | 익숙한 설명을 자기 말로 풀고, 관계가 헷갈리는 개념을 묶고 싶다. | 같은 노트의 필기와 마인드맵에 각각 정리하고 다음에 이어서 본다. |
| 자신의 자료를 공개하는 작성자 | 공부한 내용을 나누거나, 잘 만든 노트를 보여주고 싶다. | 공개 범위와 복사 권한을 고른다. 이름과 출처가 남고 자기 노트의 복사 횟수를 확인한다. |

제품은 전공·어학·독학에도 사용할 수 있다. 정보처리기사는 공개 노트가 실제 복습으로 이어지는지 확인할 첫 주제다. 파일럿의 필기·실기 구분과 참여 규모는 운영 준비에서 정한다.

### 첫 출시에서 확인할 가설

1. 같은 주제의 실제 노트를 탐색하면 스스로 찾아보지 않았던 내용을 발견한다.
2. 전체 복사가 유용한 경우, 읽고 닫는 데서 그치지 않고 사본에서 필기나 마인드맵을 편집한다.
3. 수정한 사본을 다시 열어 공부를 이어간다.
4. 작성자는 복사 권한과 출처 정책을 이해하고 자신에게 맞는 방식으로 공개한다.

의도하지 않은 획, 저장된 필기의 유실, 실수로 올린 개인 노트, 복사 권한의 우회는 첫 경험의 실패다. 파일럿에서 복사가 적다면 노트의 관련성, 탐색에서 발견할 수 있었는지, 복사 권한과 절차를 이해했는지를 따로 살펴본다.

## 2. 사용자 여정

### 2.1 새 노트로 첫 공부를 시작한다

1. 첫 실행에서 Google 또는 Apple로 로그인한다. 이후 세션이 이어지면 홈으로 들어간다.
2. 홈에서 최근 노트를 다시 열거나, 사이드바의 **새 암기노트 만들기**를 누른다.
3. **빈 필기 노트**를 고르면 빈 페이지에서 시작한다. **마인드맵**을 고르면 같은 형태의 노트가 만들어지고 마인드맵 탭이 먼저 열린다. **PDF·워드 가져오기**를 고르면 원래 페이지 위에서 시작한다.
4. 필기 탭에 손글씨와 텍스트 메모를 남기고 마인드맵 탭에서 노트 전체의 개념을 정리한다. 나중에 다시 열면 이전에 저장한 상태에서 이어 쓴다.

### 2.2 노트를 발견하고 자기 방식으로 바꾼다

1. 홈의 최신 공개 노트나 **탐색**에서 제목·태그·소개로 찾는다. 검색을 예로 들면 태그가 `정보처리기사`인 노트 중 소개에 정규화가 적힌 자료를 찾을 수 있다.
2. 카드에서 작성자와 복사 가능 여부를 확인한다. 공개 뷰어에서 필기와 마인드맵을 살펴보고, 나중에 다시 볼 자료는 즐겨찾기한다.
3. 복사 가능한 노트를 **내 노트에 복사**하면 전체가 기기에 저장되고, 보고 있던 탭에서 내 사본 편집기가 열린다.
4. 사본에서 원래 설명을 읽으면서 자기 설명을 덧붙이거나, 가져온 필기와 마인드맵을 자유롭게 고친다. 출처는 사본에 계속 남는다. 편집한 사본은 오프라인에서도 다시 열 수 있다.

### 2.3 공개한 뒤에도 개인 작업을 이어간다

1. 작성자는 공개할 계정 이름과 노트에 포함된 내용을 확인한다. 공개 단위는 필기·메모·마인드맵 전체다.
2. 전체 공개를 선택하면 **복사 허용**과 **열람만 허용** 중 하나를 직접 고른다. 공개 시점의 버전만 다른 사람에게 보인다.
3. 이후 편집은 기기에서 계속하고, 공개할 준비가 됐을 때 **공개본 업데이트**를 누른다.
4. 앱에서 복사한 노트를 다시 공개하면 `1번 원본 → 2번 수정본 → 3번 수정본`처럼 출처가 이어진다. 수정본은 별도 공개 노트로 운영된다.

## 3. 화면 구조

iPad 예시의 왼쪽 사이드바와 오른쪽 콘텐츠 영역을 홈의 기준으로 삼는다. 처음 접속하는 화면은 **홈**이다.

| 화면 | 무엇을 확인하고 무엇을 할 수 있는가 | 관련 요구사항 |
|---|---|---|
| 로그인 | Google 또는 Apple로 들어간다. 취소하거나 실패하면 다시 시도한다. | AUTH-01 |
| 홈 | 최근 작업한 내 노트를 이어서 열고, 새 노트를 만들거나 최신 공개 노트를 둘러본다. | NAV-01, NOTE-01, FIND-01 |
| 내 노트 | 최근 수정순으로 보고, 제목이나 개인 태그로 좁힌다. | NOTE-01 |
| 편집기 | 제목 아래 같은 노트의 `필기 / 마인드맵` 탭을 전환한다. 필기 탭에서 페이지를 고르고, 도구를 바꾸거나 저장 상태를 확인한다. | INK-01, INK-02, DOC-01, MAP-01 |
| 탐색 | 최신 공개 노트를 찾아보고 태그로 좁힌다. 카드에 제목·작성자·태그·복사 권한을 표시한다. | FIND-01, PUB-02 |
| 공개 노트 뷰어 | 읽기 전용으로 두 탭을 보고, 소개와 출처를 확인한다. 즐겨찾기·신고와 권한에 따른 전체 복사를 제공한다. | COPY-01, LINE-01, FIND-02, OPS-01 |
| 공유한 노트 | 현재 계정의 공개본 상태, 업데이트·비공개 전환, 복사 횟수, 운영 안내를 확인한다. | PUB-01, PUB-02, OPS-01 |
| 즐겨찾기 | 나중에 볼 공개 노트를 다시 연다. 현재 열람할 수 없는 경우 그 상태를 알 수 있다. | FIND-02 |
| 설정 | 로그아웃과 그 영향, 전체 백업과 복원을 확인한다. | AUTH-01, DATA-01, BACK-01 |

홈은 사용할 수 있는 항목을 보여준다. 실제 첫 버전에 필요한 진입점은 최근 작업, 새 노트, 최신 공개 노트다. 예시의 캘린더·학습 시간 통계·인기 순위·레벨은 각 기능을 검증하는 단계에서 추가한다.

## 4. 출시 요구사항과 사용자에게 하는 약속

아래 ID는 [구현 명세](implementation-spec.md)와 [출범 계획](project-kickoff.md)에서 같은 의미로 사용한다. **확정**은 대화에서 정한 정책, **제안 기본값**은 사용 흐름을 완성하기 위해 구체화한 정책, **미결**은 확인 이후 정할 결정이다.

| ID | 요구사항 | 출시 시 사용자에게 하는 약속 |
|---|---|---|
| AUTH-01 | 첫 로그인과 세션 | Google·Apple을 제공한다. 첫 사용은 로그인으로 시작하고 이후 세션을 유지한다. 두 로그인 방식의 계정 연결은 후순위다. |
| NAV-01 | 홈과 시작 방식 | 로그인하면 홈으로 이동한다. 새 암기노트 버튼에서 빈 필기·마인드맵·PDF/워드 중 시작 방식을 고른다. |
| NOTE-01 | 개인 노트 정리 | 제목을 변경하고 페이지를 추가·전환한다. 개인 태그, 제목 검색, 최근 수정순으로 직접 작성한 노트·가져온 문서·사본을 찾는다. |
| INK-01 | 필기 도구와 모드 | 펜·지우개·형광펜, 줄노트, 텍스트 메모를 쓴다. Pencil 전용이 기본이며, 손가락 필기를 켜면 한 손가락으로 쓰고 두 손가락으로 이동·확대한다. |
| INK-02 | 자동 저장과 이어쓰기 | 여러 페이지와 탭을 오가도 내용이 섞이지 않는다. 필기·지우기·취소/다시 실행 결과가 저장되며, 마지막 저장 상태에서 다시 시작한다. |
| DOC-01 | 외부 문서 가져오기 | PDF·워드의 원래 페이지에 필기와 메모를 덧붙이고 마인드맵으로 정리한다. 첫 출시는 외부 파일을 가져온 노트를 개인용으로 제공한다. |
| MAP-01 | 노트 전체 마인드맵 | 별도 탭에서 중심 주제와 하위 가지를 만들고, 이름과 위치를 바꾸거나 삭제한다. 초기에는 가지 간 직접 연결과 필기 페이지 연결을 연기한다. |
| DATA-01 | 기기와 계정의 경계 | 개인 노트는 같은 iPad 내에서 로그인 계정이 바뀌어도 이어 쓴다. 공개 활동과 즐겨찾기는 계정에 연결한다. 기기 내 노트는 오프라인에서 편집한다. |
| FIND-01 | 탐색과 공개 태그 | 제목·태그·선택 소개로 찾고 공개 태그로 좁힌다. 태그 입력 글자로 기존 태그를 자동완성하며 새 태그를 만들 수 있다. |
| FIND-02 | 즐겨찾기 | 마음에 드는 공개 노트를 계정의 즐겨찾기에 넣는다. 편집할 사본은 복사로 따로 만든다. |
| PUB-01 | 전체 공개와 버전 | 작성자가 공개한 시점의 버전만 제공한다. 새 수정은 공개본 업데이트 때 반영된다. 해당 계정이 자기 공개본의 비공개 전환과 관리를 한다. |
| PUB-02 | 복사 권한과 조건 | 공개할 때 두 권한 중 하나를 선택한다. 열람 전용으로 전환한 시점부터 새 복사를 막는다. 이미 만든 사본은 열 수 있다. |
| COPY-01 | 노트 전체 복사 | 필기와 마인드맵을 함께 기기에 저장하고 보던 탭에서 연다. 내용은 자유롭게 고치며 원본에는 영향이 없다. 작성자는 자기 노트의 완료 복사 횟수를 본다. |
| LINE-01 | 출처와 무료 재공개 | 사본 전체에 출처 이력을 유지한다. 복사 허용 시 출처를 남긴 무료 재공개를 허용하고 사본 판매를 금한다. 원본을 비공개로 돌리거나 삭제해도 기존 사본과 수정본은 유지한다. |
| OPS-01 | 신고와 운영 조치 | 공개 노트를 신고할 수 있다. 운영자가 저작권 문제로 내린 버전에서 파생된 공개본의 작성자에게 앱 안에서 검토를 안내한다. 문제가 확인된 공개본은 개별적으로 내린다. |
| BACK-01 | 전체 백업과 복원 | 이 iPad의 내 노트 전체를 파일 하나로 보관한다. 복원은 현재 노트를 유지하고, 변경 내용이 충돌하면 백업 쪽을 별도 복원본으로 둔다. |

### 함께 정한 세부 기본값

- **확정** · 공개 전 어느 계정으로 올리는지 표시한다. 로그아웃 전 기기에 노트가 남고 다른 계정에서 볼 수 있다는 점을 알린다. 여러 사람이 같은 iPad를 쓸 때도 이 동작이 적용된다.
- **확정** · 태그는 작성자가 직접 입력한다. 자격증 분류는 필수가 아니며, 손글씨 본문 검색과 본문 기반 태그 분석은 기획 범위에서 제외한다.
- **제안 기본값** · 공개 태그는 선택 입력으로 둔다. `정처기`와 `정보처리기사` 같은 별칭은 입력 글자만으로 합치지 않는다.
- **제안 기본값** · 첫 공개 전 작성자 표시 이름을 정한다. 로그인 이메일과 공개 표시 이름은 별도로 다룬다.
- **제안 기본값** · 취소·다시 실행 기록은 현재 편집 세션에 유지하고, 재실행 시 저장된 결과를 복원한다. 저장 실패 상태와 마지막 저장 완료 상태를 화면에서 구분한다.

## 5. 공유 정책 사례

| 상황 | 사용자 경험 |
|---|---|
| 작성자가 열람만 허용으로 공개함 | 다른 사람은 읽고 즐겨찾기할 수 있다. 카드와 상세에서 열람 전용 권한을 확인한다. |
| 작성자가 복사 허용에서 열람만 허용으로 바꿈 | 변경 이후 새 복사는 막힌다. 기존 사본과 재공개한 수정본은 그대로 열린다. |
| 작성자가 공개 후 개인 노트에 새 메모를 씀 | 새 메모는 내 iPad의 편집본에 저장된다. 공개본 업데이트를 마친 시점부터 공개 뷰어에서 보인다. |
| 원본 작성자가 비공개로 전환하거나 원본을 삭제함 | 출처의 원본은 열람할 수 없고 후속 수정본의 출처 표시와 독립 사본은 유지된다. |
| 저작권 문제가 확인된 원본을 운영자가 내림 | 파생 공개 작성자는 검토 안내를 받는다. 문제가 남은 공개 수정본은 별도 조치한다. iPad에 이미 저장한 개인 사본은 기기에 남는다. |
| 다른 계정으로 같은 iPad에서 로그인함 | 개인 노트는 그대로 보인다. 이전 계정의 공개 관리·즐겨찾기는 해당 로그인 계정의 권한에 따른다. |
| 월요일 백업을 수요일에 복원함 | 수요일에 편집한 노트는 유지하고, 내용이 다른 월요일 버전은 별도 복원본으로 추가한다. |

## 6. 개발 순서와 범위 관리

**내부 실험**은 Pencil 입력과 한 페이지 저장부터 시작한다. **개인 노트 검증**에서는 여러 노트·페이지, 파일 가져오기, 마인드맵까지 완성한다. **공유 파일럿**은 두 편집 방식이 들어간 노트로 발견·복사·복습을 검증한다. **첫 배포**에 전체 백업·복원 및 배포 심사 요건을 포함한다. 상세 전환 기준은 출범 계획서에 있다.

| 후속 검토 | 후보 |
|---|---|
| 편집·복습 | 가지 간 연결, 마인드맵 노드에서 페이지 열기, 노드 스타일·미니맵, 답 가리기와 퀴즈, 템플릿·폴더 |
| 자료 교환 | 부분 스크랩, 워드 문장 직접 편집, 블로그 활용, 한 권 단위 내보내기, Excel/CSV 왕복 교환. 마인드맵 CSV는 노드 이름과 부모·자식 관계 보존부터 검증한다. |
| 탐색과 동기 | 관심 태그 온보딩, 홈 개인화, 태그별 인기 노트·작성자, 조회수·좋아요, 랭킹·레벨·업적·보상 |
| 장기 홈과 공유 | 학습 캘린더·목표·통계, 즐겨찾기 밖의 최근 열람 기능, 이벤트, 링크 전용 공유, 외부 자료의 권한 있는 공개, 푸시·이메일 |
| 계정·저장·유료화 | Google·Apple 계정 연결, 클라우드 동기화, 전체 복사 유료화 가능성. 유료화는 파일럿 학습 후 별도 판단하고 무료 재공개 및 사본 판매 금지와의 관계를 검토한다. |

## 7. 제품 검증 기준

- **신뢰성** · 실제 iPad에서 입력 모드가 예측대로 작동하고 저장 완료된 편집이 다시 열린다. 작업 유실, 권한 우회, 백업 덮어쓰기는 단계 진행을 중단할 결함이다.
- **발견** · 수험생이 자신이 놓친 내용을 찾아내고 무엇을 참고하게 되었는지 설명할 수 있다.
- **활용** · 노트를 복사한 다음 손글씨·메모·마인드맵 중 하나를 자기 공부에 맞게 편집하고, 이후 사본을 다시 연다.
- **공개 이해** · 작성자가 기기 내 편집과 공개본의 차이, 전체 공개에 포함되는 범위, 복사 권한의 효과를 이해한다.

공개 노트의 복사 횟수와 학습 결과는 별도 신호다. 파일럿 운영은 [출범 계획서](project-kickoff.md)의 관찰 기준을 따른다. 지원 iPadOS와 워드 형식, 운영·계정 삭제 적용 범위는 해당 단계에서 검증해 결정한다.
