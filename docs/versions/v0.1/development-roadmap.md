## 1. 로드맵을 읽는 기준

- **V**는 사용자가 경험할 수 있는 제품의 범위를 나타낸다. **M0~M6**은 첫 배포까지의 개발·검증 단계다. V0~V4는 로드맵의 이름이며 스토어 버전 번호와 배포 일정은 출시 준비에서 정한다.
- **P0**는 합의된 첫 배포 범위다. V0에서 기초를 만들고 V1에서 완성한다. **P1**은 관찰된 핵심 경험의 마찰을 먼저 줄일 후보, **P2**는 반복 수요가 확인된 뒤 넓힐 후보, **P3**는 공급·운영·수익 가설을 따로 검증할 후순위다.
- V0·V1의 이름은 새로 붙였고 범위와 개발 순서는 기존 합의를 따른다. **V2 이후의 배치와 우선순위는 제안**이다. 같은 버전의 모든 후보가 한 번에 들어갈 필요는 없다. 파일럿 결과, 선행 조건, 운영 비용을 보고 가장 효과가 큰 작업부터 선택한다.
- 아래의 `합의`는 범위를 뜻한다. 현재 기능 구현 완료나 실제 배포를 뜻하지 않는다.

## 2. 버전별 사용자 경험과 전환 조건

```mermaid
flowchart LR
    A["V0 · iPad 필기와 저장 검증"] --> B["V1 · 개인 노트와 공개·복사"]
    B --> C["V2 · 복습과 노트 편집 개선"]
    C --> D["V3 · 자료 이동과 탐색 확장"]
    D --> E["V4 · 작성 동기와 수익 실험"]
```

| 버전 | 이 버전에서 더 할 수 있는 일 | 착수·배포 판단 |
|---|---|---|
| **V0 · 내부 필기 프로토타입** | 한 페이지에서 Pencil 또는 손가락으로 쓰고 지운다. 실행 취소·다시 실행과 기기 내 자동 저장으로 종료 후 이어 쓴다. | M0~M2. 실제 iPad에서 손바닥·제스처·입력 전환을 검증하고, 저장 완료 결과의 강제 종료 복원과 쓰기 실패 후 재시도를 확인한다. |
| **V1 · 첫 배포** | 홈에서 개인 노트 또는 PDF·워드 노트를 시작한다. 필기와 마인드맵을 같은 노트에 쓰고, 공개 노트를 찾고 복사해 자기 자료로 바꾼다. 기기 내 라이브러리를 백업하고 복원한다. | M3 개인 노트 → M4 마인드맵 → M5 정보처리기사 공유 파일럿 → M6 첫 공개 배포. 사본 편집·재열람과 권한·운영을 확인하고, 첫 공개 배포 전 전체 백업·복원과 배포 심사 항목을 검증한다. |
| **V2 · 복습과 편집 개선** | 복사한 노트에서 필요한 설명을 더 빨리 다시 찾고, 작은 단위로 가져오거나 가리고 복습한다. 반복적인 노트 편집과 정리에 드는 시간을 줄인다. | V1 파일럿에서 반복된 마찰을 확인한 뒤 한 가지 이상을 검증한다. 페이지·노드·출처가 기존 노트와 백업에서 계속 보존되는지 확인한다. |
| **V3 · 자료 이동과 탐색 확장** | 다른 도구·기기와 노트를 교환하고, 공개 자료가 많아지면 관심 주제로 원하는 내용을 찾는다. 검증한 권한에 맞춰 공유 경로를 넓힌다. | 파일 교환·기기 변경·탐색 수요를 각각 확인한다. 데이터 이동 기능은 손실·충돌 복구 기준, 탐색 기능은 태그별 실제 자료량을 확보한 뒤 진행한다. |
| **V4 · 작성 동기와 수익 실험** | 작성자가 공개 노트의 반응을 확인한다. 학습 리듬과 기여를 돕는 기능이나 과금 방식을 시험한다. | 공개 자료 공급과 열람·복사·재열람이 반복된다는 근거가 필요하다. 지표 조작 대응, 운영 비용, 작성자 동의와 복사 권한의 영향을 검토한 뒤 실험별로 판단한다. |

V1 내부에서는 **개인 노트 → 마인드맵 → 공개·복사** 순서를 유지한다. V2 이후는 제품이 발전하는 기본 방향이다. 의존성이 독립적이면 V3 후보라도 근거가 충분할 때 앞당길 수 있으며, V4의 보상·과금은 그 기능의 선행 조건을 먼저 확인한다.

## 3. P0 · 확정된 V0와 V1 범위

| 버전·단계 | 기능 | 완료 기준 또는 관련 요구사항 |
|---|---|---|
| V0 · M0 | Xcode·서명·실기기 준비 | 실제 iPad에서 앱을 실행한다. |
| V0 · M1 | Pencil 필기, 펜·지우개, 손가락 필기 토글, 이동·확대 | Pencil 전용이 기본이며 토글을 재실행 후 유지한다. 손바닥·두 손가락 입력에서 원치 않는 획이 생기지 않는다. INK-01 일부. |
| V0 · M2 | 한 페이지 자동 저장·복원, 실행 취소·다시 실행, 실패 재시도 | 종료 뒤 마지막 저장 상태와 지운 결과가 복원된다. 쓰기 실패 시 이전 저장본과 편집을 보존한다. INK-02 일부. |
| V1 · M3 | 홈, 새 암기노트 시작 방식, 내 노트, 제목·개인 태그·최근 수정순 | 홈에서 새 노트 시작 방식을 고르거나 기존 노트를 연다. 여러 페이지와 노트의 편집이 섞이지 않는다. NAV-01, NOTE-01. |
| V1 · M3 | 여러 페이지, 형광펜·줄노트·텍스트 메모, PDF·워드 가져오기 | 외부 문서의 원래 페이지 위에 필기와 메모를 추가하고 오프라인에서 다시 연다. 지원 워드 형식과 변환 방식은 구현 시 검증한다. INK-01/02, DOC-01. |
| V1 · M4 | 같은 노트의 필기·마인드맵 탭 | 직접 만든 노트와 가져온 노트 모두 두 탭이 있다. 중심 주제와 하위 가지를 편집하고 재실행 후 관계와 좌표가 복원된다. MAP-01. |
| V1 · M5 | Google·Apple 첫 로그인과 세션, 기기와 계정의 경계 | 첫 실행에서 로그인하고 이후 세션을 유지한다. 개인 노트는 같은 iPad에, 공개 관리·즐겨찾기는 계정에 귀속된다. AUTH-01, DATA-01. |
| V1 · M5 | 홈 최신 공개 노트, 제목·태그·소개 검색, 태그 필터·자동완성, 즐겨찾기 | 작성자가 태그를 입력하며 기존 태그를 재사용하거나 새로 만든다. 공개 노트를 읽고 즐겨찾기에 둘 수 있다. FIND-01/02. |
| V1 · M5 | 전체 공개·비공개, 공개본 업데이트, 열람 전용·복사 허용 | 작성자가 전체 노트의 공개 범위와 복사 권한을 고른다. 자동 저장된 개인 변경은 공개본 업데이트 때 반영된다. 가져온 PDF·워드 노트는 개인용으로 운영한다. PUB-01/02, DOC-01. |
| V1 · M5 | 전체 복사, 독립 사본, 출처와 무료 재공개, 작성자용 완료 복사 횟수 | 두 탭을 한꺼번에 복사해 보던 탭에서 편집한다. 출처가 이어지고 권한 변경·원본 비공개 뒤에도 기존 사본은 유지된다. 사본 판매를 금한다. COPY-01, LINE-01. |
| V1 · M5 | 신고, 운영자가 개별 공개본을 내리기, 파생 작성자 안내 | 문제가 있는 공개본을 개별 처리하고 저작권 문제는 관련 공개 수정본 작성자에게 앱 안에서 안내한다. OPS-01. |
| V1 · M6 | 수동 전체 백업·복원과 공개 배포 준비 | 현재 라이브러리를 보존하며, 변경 충돌은 별도 복원본으로 추가한다. App Store의 계정 삭제·UGC·개인정보 적용 요건을 출시 전에 확인한다. BACK-01. |

V1의 상세 완료 기준은 [출범 계획서 M3~M6](project-kickoff.md#3-개발-단계와-전환-조건)를 따른다. 장기간 사용하는 파일럿이면 전체 백업 검증을 앞당길 수 있다. 필기 유실, 복원 덮어쓰기, 권한 우회, 비공개 데이터 노출, 출처 유실은 후속 기능보다 먼저 처리한다.

## 4. V2 이후 기능별 우선순위

아래 항목은 모두 **후속 후보**다. 버전과 우선순위는 초기 제안이며, 착수 신호가 확인되기 전에는 범위를 확정하지 않는다.

| ID | 제안 버전·우선순위 | 기능 | 선행 기능과 착수 신호 |
|---|---|---|---|
| R-01 | V2 · P1 | 마인드맵 노드에서 같은 노트의 필기 페이지 열기 | 페이지 ID와 복사 시 대응 관계가 필요하다. 사용자가 세부 설명을 찾으려고 두 탭을 반복해서 오갈 때 한 노드에서 한 페이지 연결부터 검증한다. |
| R-02 | V2 · P1 | 부분 스크랩 | V1 전체 복사와 출처 규칙을 사용한다. 전체를 복사한 뒤 대부분을 지우거나 일부 설명만 가져가는 일이 반복되면, 스크랩 대상 단위와 출처 표시부터 정한다. |
| R-03 | V2 · P1 | 답 가리기와 확인, 이후 퀴즈 | 노트 재열람·복습 행동이 먼저 확인돼야 한다. 가리고 떠올려 보는 수요가 있으면 사용자 지정 영역이나 항목을 먼저 검증한다. |
| R-04 | V2 · P2 | 마인드맵 가지 간 연결 | 기본 트리가 여러 노트에서 안정적으로 쓰이고, 서로 다른 가지를 잇고 싶다는 요구가 반복될 때 데이터 호환과 연결 편집 방식을 확인한다. |
| R-05 | V2 · P2 | 노드 스타일·미니맵 | 큰 맵에서 화면 위치를 잃거나 관계를 구분하기 어려울 때 원하는 기능부터 고른다. |
| R-06 | V2 · P2 | 노트 템플릿 | 사용자가 같은 배치·페이지 구성을 반복해서 만들 때 실제로 재사용하는 양식부터 제공한다. |
| R-07 | V2 · P2 | 폴더와 노트 분류 확장 | 개인 태그·제목 검색으로 찾기 어려운 규모와 상황을 확인한다. 기존 태그와 폴더의 동작이 함께 설명돼야 한다. |
| R-08 | V3 · P2 | 마인드맵 CSV 가져오기·내보내기 | Excel로 구조를 만들거나 수정할 수요를 확인한다. CSV 왕복에서 노드 이름과 부모·자식 관계가 보존되는 것이 첫 완료 기준이다. 자유필기 내보내기는 범위를 따로 정한다. |
| R-09 | V3 · P2 | 노트 한 권 내보내기·백업 | 전체 백업을 검증한 뒤 특정 노트만 보관하거나 이동하는 수요가 있을 때 대상 형식과 편집 가능 여부를 정한다. |
| R-10 | V3 · P2 | 워드 원문 편집 | 문서 위 필기와 메모로 해결하기 어려운 수정 수요를 확인한다. 원문 편집 후 페이지 배치와 주석 연결을 유지할 방식을 먼저 검증한다. |
| R-11 | V3 · P2 | 블로그 등 외부 콘텐츠 활용 | 링크 보관과 본문 가져오기의 필요 및 재배포 권한을 구체화한다. 공개 기능에 붙이려면 R-13의 관련 권한 검토를 선행한다. |
| R-12 | V3 · P2 | 링크 전용 공유 | 전체 공개를 꺼리는 스터디 수요가 확인되면 링크 노출과 권한 만료·철회 동작을 정한다. 특정 수신자 지정은 수요를 따로 확인한다. |
| R-13 | V3 · P2 | 외부 자료를 가져온 노트의 공개 | 직접 만든 PDF·워드나 재배포 가능한 콘텐츠를 올릴 수요가 있을 때 공개·복사·신고 기준을 검증한다. |
| R-14 | V3 · P2 | 수동 백업 이후의 자동 백업·기기 간 동기화 | 여러 기기에서 이어 쓰려는 수요가 확인돼야 한다. 현재 기기 귀속 노트와 계정 연결, 충돌·삭제·복구 정책 및 운영 비용을 결정한다. |
| R-15 | V3 · P2 | Google·Apple 계정 연결 | 두 로그인 방식을 가진 중복 계정 문제가 반복될 때 제공자 인증과 기존 공개본·즐겨찾기에 미치는 영향을 정한다. |
| R-16 | V3 · P2 | 선택형 관심 태그와 홈 개인화·태그 클라우드 | 태그별 볼 만한 공개 노트가 쌓여야 한다. 관심 태그 선택은 건너뛸 수 있게 하고, 사용자가 고른 태그 노트를 먼저 보여주는 방식부터 검증한다. |
| R-17 | V3 · P2 | 최근 본 공개 노트 | 즐겨찾기에 넣지 않은 자료를 반복해서 다시 찾고 싶어 할 때 기록 보관과 접근 중단 상태를 정의한다. |
| R-18 | V3 · P2 | 푸시·이메일 안내 | 앱 내 공지만으로 저작권 검토나 공유 변경을 제때 알기 어려운 사례가 쌓이면 대상 안내와 수신 설정을 좁혀 적용한다. |
| R-19 | V4 · P3 | 좋아요와 공개 조회수, 작성자용 추가 통계 | V1에는 작성자만 보는 완료 복사 횟수가 있다. 추가 반응이 사용자나 작성자의 판단에 도움이 되는지 확인하고 중복 집계 처리 기준을 둔다. |
| R-20 | V4 · P3 | 인기순, 태그별 노트·작성자 랭킹 | 태그별 콘텐츠·활동이 충분하고 R-19에서 신뢰할 수 있는 지표가 준비돼야 한다. 조회 중심·복사 중심 등 지표가 만드는 차이와 조작 가능성을 비교한다. |
| R-21 | V4 · P3 | 학습 캘린더·목표·시간·활동 통계 | 사용자가 기록을 다시 보고 학습을 이어가는 데 도움을 받을 때 시도한다. 무엇을 학습 시간으로 셀지와 개인정보 처리 기준을 먼저 정한다. |
| R-22 | V4 · P3 | 레벨·업적·보상·랭킹 이벤트 | 반복적인 작성·공유와 R-19~R-20 지표의 신뢰성을 확인한다. 보상은 조회수 부풀리기나 저품질 공개를 유도할 수 있어 작은 실험으로 검증한다. |
| R-23 | V4 · P3 | 전체 복사 유료화 검토 | 복사한 노트를 실제로 편집·재열람하는 수요가 검증된 뒤 가격·권한·작성자 동의와 기존 무료 재공개·사본 판매 금지 정책의 관계를 별도로 결정한다. |

**제외 결정** · 손글씨 본문 검색과 노트 내용을 분석해 태그를 자동 지정하는 기능은 로드맵 항목으로 편성하지 않는다. 공개 노트는 제목·태그·소개로 찾고, 자동완성은 작성자가 입력한 태그 글자를 기준으로 한다.

## 5. 우선순위를 다시 정하는 방법

1. **관찰 사실을 기록한다.** 수험생이 공개 노트에서 무엇을 찾았는지, 복사한 사본을 편집했는지, 다음 공부에 다시 열었는지를 확인한다. 복사 횟수는 학습 결과와 구분한다.
2. **원인과 후보를 연결한다.** 예를 들어 놓친 개념을 발견했지만 문서 전체를 가져오고 싶지 않았다는 행동이 반복되면 R-02를 검토한다. 최근 사본은 잘 열리지만 세부 설명을 찾느라 두 탭을 계속 왕복한다면 R-01을 검토한다.
3. **선행 조건을 확인한다.** 순서를 앞당겨도 기존 노트와 백업, 공개 권한과 출처가 안전하게 유지되어야 한다. 운영 부담이 있는 기능에는 담당과 대응 경로를 둔다.
4. **변경 근거를 남긴다.** 기능 ID, 관찰한 문제, 변경 전후의 버전·우선순위, 남은 선행 조건, 완료 기준을 같이 기록한다. V1의 출시 약속을 바꾸는 결정은 제품 기획서와 구현 명세서에도 반영한다.
