# Me-mento 구현 명세서

문서 v1.1 · 2026-11-26 · 제품 V0~V1 구현 계약

[제품 기획서](product-plan.md) · [프로젝트 출범 계획서](project-kickoff.md) · [개발 로드맵](development-roadmap.md) · [문서 목록과 개정 이력](README.md)

이 문서는 요구사항 ID로 사용자 행동, 시스템 경계, 상태 전이, 오류 대응, 인수 시나리오를 연결한다. 필드와 작업 이름은 논리 계약이다. 저장 라이브러리, 서버 제공자, 엔드포인트 구조, 구체적인 제한값은 구현 단계에서 정한다. 세부 제안은 **구현 기본값**으로 읽는다. 제품 변경이 필요한 경우 기획서의 해당 요구사항과 출시 기준을 함께 수정한다.

V0는 한 페이지 필기·저장의 검증 범위다. V1의 전체 구현 계약은 아래 요구사항 ID를 사용한다. V2 이후 기능의 착수 판단은 로드맵에 있으며, 각 후보가 확정될 때 별도 계약과 인수 기준을 추가한다.

## 1. 기술 경계와 데이터 모델

| 엔터티 | 주요 데이터 | 저장 위치와 무결성 |
|---|---|---|
| 설치 상태 | 로그인 완료 여부, 명시적 로그아웃 여부, 필기 입력 설정 | 기기. 인증 자격 증명과 개인 노트 데이터를 분리한다. |
| 개인 노트 | 노트 ID, 제목, 원본 종류, 개인 태그, 페이지 순서, 마인드맵 ID, 수정 시각, 마지막 탭·페이지, 출처 | 기기. 제목·순서·계정이 바뀌어도 ID를 유지한다. |
| 필기 페이지 | 페이지 ID, 노트 ID, 페이지 크기, 배경 또는 문서 페이지 참조, 손글씨, 텍스트 메모 | 기기. 획과 메모는 페이지 좌표를 기준으로 보관한다. |
| 가져온 파일 자료 | 보관된 자료와 렌더링 결과, 형식, 페이지 연결 | 기기. 오프라인 열람과 백업을 위해 노트가 참조하는 자료를 함께 보존한다. |
| 마인드맵 | 루트 ID, 노드 ID, 부모 ID, 이름, 위치 | 기기 및 버전의 스냅샷. 한 루트에서 모든 노드에 도달할 수 있고 순환과 고아 노드가 없어야 한다. |
| 계정 | 계정 ID, 제공자와 검증된 주체 식별자, 작성자 표시 이름 | 서버. Google·Apple 이메일이 같아도 식별자를 병합하지 않는다. |
| 공개 노트 | 공개 ID, 작성 계정, 공개 여부, 복사 권한, 현재 버전, 최초 공개 시각, 운영 상태 | 서버. 작성 계정과 현재 버전을 권한 판단에 사용한다. |
| 공개 버전 | 버전 ID, 공개 ID, 제목·태그·소개, 페이지·마인드맵 묶음, 직전 출처 | 서버. 버전의 콘텐츠는 고정한다. 공개 권한·운영 상태는 접근 결정 시 별도로 확인한다. |
| 사본 출처 | 직접 복사한 버전 ID, 상위 계보, 발급 당시 재공개 권한 근거 | 서버에서 검증하고 사본·백업에서 보존한다. 표시용 이름은 출처 증명과 별도로 취급한다. |
| 계정별 활동 | 즐겨찾기, 완료 복사 집계, 신고, 운영 조치, 파생본 검토 안내 | 서버. 작성자 지표와 운영 활동에 별도의 조회 권한을 적용한다. |
| 전체 백업 | 형식 버전, 노트·자료 목록, 레코드와 첨부 참조, 출처·제한 | 파일. 복원 전에 완결성과 참조를 검사한다. |

- 구매·계정 연결·클라우드 개인 라이브러리 동기화 모델은 후속 범위다.
- 사본은 독립 노트 ID와 페이지·노드 식별자를 가진다. 참조를 다시 연결한 뒤 로컬에 반영한다. 공개본 관리 연결은 로컬 ID와 현재 계정에 따라 조회한다.
- **구현 기본값**으로 로컬 저장·백업과 공개 콘텐츠 묶음에 각자의 형식 버전을 둔다. 모르는 버전이 열리면 저장된 자료를 유지하고 지원 범위를 안내한다.

## 2. 세션, 홈, 개인 노트 · AUTH-01 / DATA-01 / NAV-01 / NOTE-01

| 입력 상태 | 허용되는 행동 | 화면과 결과 |
|---|---|---|
| 처음 설치 또는 명시적으로 로그아웃함 | Google·Apple 로그인 | 로그인 성공 후 홈으로 간다. 실패·취소는 다시 시도할 수 있다. |
| 인증 세션 유효, 온라인 | 로컬 편집과 모든 계정 기능 | 홈에 최근 노트와 최신 공개 노트가 보인다. 각 영역을 독립적으로 로드한다. |
| 이 설치에서 로그인 이력 있음, 명시적 로그아웃 없음, 오프라인 | 저장된 노트 열기·편집·수동 백업·복원 | 세션 만료 여부와 관계없이 로컬 홈을 제공한다. 온라인 기능은 연결 필요 상태를 표시한다. |
| 온라인이며 재인증이 필요함 | 재인증 및 저장 중인 로컬 작업 보호 | 서버 요청을 중단하고 로그인 안내를 표시한다. 로컬 데이터와 완료한 저장을 유지한다. |
| 다른 계정으로 로그인함 | 기존 기기 내 노트 사용과 새 계정의 공개 기능 | 공개 관리·즐겨찾기·공지·복사 횟수는 새 계정으로 다시 조회한다. 이전 계정 응답이나 캐시가 섞이지 않게 한다. |

로그아웃 직전 기기에 노트가 남는다고 안내한다. 계정 삭제 정책은 배포 전에 정하고, 계정 삭제 화면에서 서버 데이터와 기기 내 데이터에 각각 무슨 일이 생기는지 표시한다.

### 화면 전이 계약

- **홈**은 최근 수정한 로컬 노트가 있으면 표시한다. 공개 조회 실패를 로컬 영역과 분리한다.
- **새 노트**는 시작 선택지를 표시한다. 취소하거나 파일을 고르지 않으면 노트를 만들지 않는다. 빈 필기와 마인드맵은 같은 노트 구조로 시작하고 첫 탭만 다르다.
- **내 노트**는 개인 태그 필터, 제목 검색, 최근 수정순을 지원한다. 단순 열람으로 수정 시간을 갱신하지 않는다.
- **편집기**는 탭과 페이지 위치를 마지막 저장 상태에서 복원한다. 선택한 페이지가 사라졌으면 남은 첫 페이지를 사용한다는 구현 기본값을 적용한다.
- **탐색·즐겨찾기**는 로드 중, 결과 없음, 통신 실패, 접근 중단을 구별한다. 즐겨찾기는 사본을 생성하지 않는다.
- **공유한 노트**는 현재 계정이 관리할 수 있는 항목, 현재 상태, 작성자용 복사 횟수와 검토 안내를 표시한다.

## 3. 편집기와 로컬 저장 · INK-01 / INK-02 / DOC-01 / MAP-01

### 3.1 입력과 페이지

- PencilKit을 첫 실험 후보로 사용한다. `.pencilOnly`와 `.anyInput`을 전환하고, 앱의 이동·확대 입력은 별도로 실기기에서 검증한다. [PencilKit drawingPolicy](https://developer.apple.com/documentation/pencilkit/pkcanvasview/drawingpolicy)
- 손가락 필기 기본값은 꺼짐이다. 꺼짐에서 손가락은 이동·확대를 담당한다. 켜짐에서는 한 손가락이 획 또는 지우개, 두 손가락이 이동·확대를 담당한다. 도구와 켜짐 상태를 화면으로 확인할 수 있다. 입력 모드 선택은 재실행 후 유지한다.
- 순차적으로 펜, 지우개, 취소·다시 실행, 형광펜, 줄노트, 텍스트 메모를 검증한다. 텍스트 메모와 획은 페이지 좌표로 결합한다. 확대와 회전 후에도 동일 위치를 가리킨다.
- 획을 저장할 때 활성 노트 및 페이지 ID를 함께 넘긴다. 탭·페이지 전환 이후 도착한 저장 결과가 새 페이지의 표시나 데이터를 바꾸지 않도록 작업 상태를 분리한다.
- **구현 기본값**으로 취소·다시 실행은 현재 세션에서 처리한다. 재실행 시 마지막 저장 결과부터 시작한다.

### 3.2 저장 전이

| 상태 | 진입 조건 | 요구 동작 |
|---|---|---|
| 변경 발생 | 획 완료, 지우기, 취소·다시 실행, 메모 수정, 구조 변경 | 변경을 해당 레코드와 연결하고 저장을 예약한다. |
| 저장 중 | 레코드 저장 시작 | 같은 레코드로 추가 변경이 오면 후속 저장으로 이어간다. 탭을 바꿔도 이전 페이지를 대상으로 완료한다. |
| 저장 완료 | 최신 대상 변경의 기록 성공 | 완료 상태를 표시한다. 페이지·탭·앱 재실행에서 결과를 읽는다. |
| 저장 실패 | 쓰기 실패, 공간 부족, 읽기 오류 | 해당 변경을 편집기에 유지하고 실패와 재시도를 표시한다. 이전 정상 저장본을 보존한다. |

- 백그라운드 진입과 편집기 이탈 전에는 대기 중인 완료된 획을 가능한 범위에서 기록한다. 종료 직전 미완료 획까지 저장된 것으로 표시하지 않는다.
- **구현 기본값**으로 마지막 정상 저장본을 유지하는 교체·트랜잭션 방식을 선택한다. 저장 순서가 뒤바뀌어 오래된 값이 최신 값에 덮이지 않아야 한다.
- 앱이 비정상 종료되면 마지막 저장 성공까지 복구한다. 로컬 스키마를 바꿀 때 기존 데이터로 이전·재실행 테스트를 한다.

### 3.3 PDF·워드 가져오기

1. 파일 선택 후 지원 형식, 파일 접근, 암호화·손상 여부를 확인한다. 취소는 정상 종료 상태다.
2. 원문과 페이지 표현을 기기 보관 공간에 준비한다. 노트 페이지 ID를 할당하고 페이지마다 크기와 원본 연결을 기록한다.
3. 자료 준비와 목록 등록이 모두 성공하면 필기 탭을 연다. 실패하면 이유와 재시도 경로를 보여주고 불완전한 노트는 목록에 노출하지 않는다.
4. 다시 열 때 원래 파일 위치에 의존하지 않는다. 가져온 페이지를 바탕으로 텍스트 메모와 손글씨를 렌더링한다.
5. 가져오기에서 생성된 노트의 공개 제한을 보존한다. 공개 진입·파일 등록·백업 복원 경로에서 관련 상태를 유지하고, 공개 업로드는 첫 범위에서 허용하는 콘텐츠 구조만 처리한다.

**착수 시 결정**으로 `.docx`와 레거시 `.doc` 지원 경계, 페이지 표현 방식, 오프라인 준비 가능 여부를 검증한다. 한글 줄바꿈, 표, 삽입 이미지, 페이지 나눔을 대표 자료로 확인한다. 사용자 문서를 외부 변환 서비스에 전송하는 방식은 데이터 처리 범위를 검토한 뒤 채택 여부를 별도로 결정한다.

### 3.4 마인드맵

- 같은 노트의 마인드맵 탭에서 루트 하나와 여러 수준의 가지를 편집한다. 노드 추가, 이름 변경, 위치 이동, 하위 가지 삭제, 화면 이동과 확대를 제공한다.
- **구현 기본값**으로 처음 생성한 루트 이름을 노트 제목으로 채우고, 이후 각각 편집한다. 이동은 노드 좌표만 변경한다. 하위 가지를 삭제하면 자식도 함께 삭제하며 범위를 표시한다.
- 저장과 복사 경로에서는 루트 하나, 중복 ID 없음, 각 비루트 노드의 유효한 부모, 순환 없음, 모든 노드의 도달 가능성을 검증한다.
- 복사와 백업 후에도 이름·부모 관계·위치가 유지된다. 공개 뷰어에서는 저장된 트리를 읽기 전용으로 제공한다.

## 4. 탐색과 즐겨찾기 · FIND-01 / FIND-02

- 공개 목록과 검색은 현재 열람 가능한 항목을 대상으로 한다. 검색 범위는 제목·태그·선택 소개이며, 공개 태그로 필터링한다. 최신순 기준은 최초 공개 시각을 사용한다는 구현 기본값을 적용한다. 동률 정렬에 안정적인 기준을 둔다.
- 태그 자동완성은 입력한 접두사로 기존 태그를 찾는다. 앞뒤 공백과 유니코드 표기 차이의 정규화를 적용하고 글자가 같은 태그의 중복 생성을 막는다. `정처기`와 `정보처리기사`는 별칭 규칙이 도입되기 전까지 별도 태그다. 새 노트에 태그를 강제하지 않는다.
- 즐겨찾기는 현재 계정과 공개 ID를 연결한다. 추가·해제 재시도에 같은 결과를 유지한다. 항목을 다시 열 때 현재 공개 상태를 확인한다. 접근 중단 상태라면 중단됐다고 표시한다.
- 네트워크 없는 상태와 검색 결과 없음의 내용을 구분한다. 홈에서 공개 영역 오류가 발생해도 로컬 노트 기능을 사용할 수 있다.

## 5. 공개 및 복사 권한 · PUB-01 / PUB-02 / COPY-01 / LINE-01

### 5.1 가시성과 권한 판정

| 공개 노트의 유효 상태 | 탐색·상세 | 즐겨찾기 새 등록 | 새 복사 | 관리 |
|---|---|---|---|---|
| 개인용 또는 비공개 | 타인이 접근할 수 없음 | 불가 | 불가 | 작성 계정이 공개하거나 관리 |
| 전체 공개 · 복사 허용 | 로그인 사용자에게 노출 | 가능 | 가능 | 작성 계정이 업데이트·권한 변경·비공개 전환 |
| 전체 공개 · 열람만 허용 | 로그인 사용자에게 노출 | 가능 | 불가 | 작성 계정이 업데이트·권한 변경·비공개 전환 |
| 운영 중단 | 접근 중단 | 불가 | 불가 | 운영 정책에 따라 검토 가능 |

외부 문서가 포함된 노트는 첫 출시의 공개 대상에서 제외한다. 사본의 재공개는 해당 사본에 발급된 권한이 있어야 한다. 공개 권한은 목록과 뷰어에 표시하고, 요청마다 서버에서 다시 확인한다. 이전 화면 또는 직접 접근 경로에서도 같은 정책을 적용한다.

### 5.2 공개 작업 계약

1. 작성자는 공개할 계정, 전체 노트 내용, 제목·태그·소개, 공개 조건, 복사 권한을 확인한다. 두 권한 중 하나를 명시적으로 선택한다.
2. 서버는 계정 및 공개 권한을 확인하고, 기존 공개본 업데이트라면 작성 계정의 관리 권한을 확인한다. 사본이라면 출처와 재공개 권한을 검증한다.
3. 전달받은 노트와 첨부 자료를 검증한 뒤 새 버전을 만들고 현재 버전으로 노출한다. 중간 업로드나 검증 실패는 이전 공개본에 영향을 주지 않는다.
4. 공개 요청을 확정할 때 업로드할 문서와 공개 메타데이터를 고정한다. 공개 처리가 성공하면 그 묶음을 노출한다. 업로드 중의 iPad 편집은 기기 내 변경으로 저장하며 진행 중인 공개본에는 반영하지 않는다.
5. 권한 변경이나 비공개 전환은 서버 적용 후 성공을 표시한다. 이미 보관된 사본의 열람·편집·무료 재공개 권한은 일반적인 공개 상태 변경으로 소급 변경하지 않는다.
6. **구현 기본값**으로 같은 로컬 노트를 다른 계정이 공개하면 그 계정의 별도 공개 항목을 만든다. 이전 계정의 관리 권한을 이전하지 않는다.

### 5.3 복사 작업 계약

- 요청에는 공개 ID, 뷰어에서 본 버전, 이번 시도를 식별할 작업 ID가 필요하다. **구현 기본값**으로 서버는 현재 표시할 수 있는 버전에서만 새 복사를 시작한다. 뷰어가 이전 버전을 보고 있다면 공개 상태와 권한을 확인해 최신 버전을 다시 보여주고 사용자가 이어서 복사할 수 있게 한다.
- 서버에서 유효한 인증, 공개 상태, 복사 권한을 확인한다. 권한이 없으면 복사 묶음·출처 근거를 제공하지 않는다. 이전 화면에 복사 버튼이 표시돼 있어도 서버의 현재 상태로 판정한다.
- 앱은 반환된 공개 버전 전체를 검증하고 새 노트 ID로 기기에 저장한다. 공개 태그와 작성자 개인 태그는 개별 개념으로 처리하며 원래 작성자의 개인 태그를 전달받지 않는다.
- 로컬 등록을 완료한 뒤 뷰어에서 보고 있던 탭의 편집기를 연다. 같은 필기 페이지를 재연결할 수 있으면 해당 페이지를 열고, 대응 페이지가 없으면 첫 페이지를 연다.
- 네트워크 실패, 저장 실패, 중복 탭 후 재시도는 동일 작업 ID를 쓴다. 동일 작업은 완성된 사본이 한 개만 남는다. 사용자가 나중에 새로 복사하는 동작은 새 ID를 쓰고 별도 사본을 생성할 수 있다.
- 작성자용 복사 횟수는 승인 요청이나 상세 열람과 구별한다. **구현 기본값**으로 기기 저장 완료를 서버에 확인한 복사 작업을 집계한다. 확인 전 연결이 끊기면 같은 ID로 재전송해 한 번만 반영한다. 확인을 하지 못한 시점의 표시 값은 일시적으로 늦을 수 있다.

### 5.4 출처와 재공개

- 각 신규 사본은 직접 복사한 공개 버전과 선행 출처 관계를 보존한다. 출처는 편집·백업·복원으로 제거되지 않고, 공개 시 서버도 검증한다.
- 출처에 딸린 재공개 권한은 사본을 따라 유지된다. 동일 iPad에서 다른 계정으로 바꾸거나 백업으로 다른 iPad에 복원한 경우에도 적용한다. 현재 계정은 자신이 만든 새 공개 항목을 관리한다.
- 상위 작성자가 일반 비공개·삭제를 선택하면 이후 원본 콘텐츠 열람을 막는다. 출처에는 해당 단계와 열람 불가 상태를 표시한다. 삭제한 사용자의 이름에 관한 보존 정책은 계정 정책과 함께 정한다.
- 후속 작성자가 앞선 원본 콘텐츠를 고쳐도 출처 흐름은 유지한다. 사본 판매 제한과 무료 재공개 조건은 공개 선택 화면과 관련 정책에 표시한다.

## 6. 신고와 운영 · OPS-01

| 작업 | 처리 기준 | 저장과 표시 |
|---|---|---|
| 신고 접수 | 로그인 사용자가 열람한 공개 버전과 사유를 보냄 | 신고 ID, 대상 버전, 사유·선택 설명, 접수 시각을 기록하고 접수 결과를 보여준다. |

## 7. 전체 백업과 복원 · BACK-01

1. 백업은 실행 시점의 로컬 라이브러리와 연결된 첨부 자료를 하나의 일관된 파일로 준비한다. 마지막으로 완료된 저장의 시점을 사용자에게 설명할 수 있어야 한다.
2. 백업에 노트 ID, 수정 내용, 개인 태그, 페이지와 마인드맵, 가져온 자료, 출처와 공개 제한을 담는다. 계정 자격 증명과 서버의 계정별 즐겨찾기·공개 상태·관리 권한은 백업에 넣지 않는다.
3. 사용자가 선택한 위치에 저장한 뒤 실제로 완성된 파일을 확인한다. 취소나 쓰기 실패에 기존 라이브러리를 유지한다.
4. 복원 전에 형식 버전, 목록, 첨부 누락, 참조 오류, 저장 공간을 확인한다. 복원할 노트와 충돌을 미리 보여준다.
5. 복원은 아래 표대로 현재 상태를 보존한다. 여러 노트 중 일부만 추가될 가능성이 있는 경우, 작업을 완료하기 전에 데이터와 첨부를 준비하고 오류를 표시한다.
6. 취소·형식 미지원·파일 오류에는 기존 노트를 유지한다. 결과에 추가, 별도 사본, 건너뜀을 표시한다.

| 비교 결과 | 처리 |
|---|---|
| 같은 원본 ID가 현재 기기에 없음 | 백업 노트를 추가한다. |
| 같은 원본 ID와 동일 내용 | 건너뛴다. |
| 같은 원본 ID와 다른 내용 | 기존 노트를 유지하고 새 ID의 `복원본`을 만든다. |
| 같은 충돌 버전을 이전 복원에서 추가함 | 원본 ID와 백업의 내용 식별값으로 이전 결과를 확인하고 중복을 건너뛴다. |

**구현 기본값**으로 내용 비교는 페이지·필기·메모·마인드맵·개인 태그·첨부와 같은 편집 자료를 기준으로 한다. 단순 열람 위치 차이만으로 복원본을 생성하지 않는다.

## 8. 작업 완료와 재시도 표준

| 상황 | 실패 상태에서 보존할 것 | 다음 시도 |
|---|---|---|
| 로컬 저장 실패 | 현재 화면의 편집과 이전 저장본 | 같은 변경을 다시 저장한다. |
| 가져오기 실패 | 기존 노트와 파일 | 원인을 안내하고 파일을 다시 고를 수 있다. |
| 공개 업로드 실패 | 기기 내 노트와 이전 공개본 | 같은 요청의 결과를 조회하거나 재시도한다. |

| 백업·복원 실패 | 현재 라이브러리와 정상 백업 파일 | 이유를 표시하고 파일 또는 저장 위치를 다시 고른다. |

**공통 검증**으로 사용자에게 완료를 표시하는 시점은 영속화 이후다. 인증 실패·권한 변경·연결 실패·데이터 오류를 UI에서 구별한다. 공개 조작과 계정 조회에는 유효한 서버 권한이 필요하다.

| V-17 | BACK-01, LINE-01 | 동일·신규·변경 충돌 노트를 포함한 전체 백업을 다른 기기와 기존 자료가 있는 기기에 복원한다. 두 번째 복원에 동일 충돌 사본이 쌓이지 않고, 복사 노트의 출처와 재공개 권한이 새 기기에서도 유지된다. |
| V-18 | BACK-01 | 첨부 누락, 손상, 용량 부족 또는 취소를 시도한다. 현재 라이브러리가 유지되고 결과를 구분할 수 있다. |
| V-19 | PUB-01, OPS-01, DATA-01 | 다른 로그인 계정과 일반 계정으로 각각 공개본 변경·운영 조치·작성자 지표 조회를 시도한다. 허용된 주체만 작업할 수 있다. |

이 표는 실행할 테스트 목록이다. 실기기 결과, 시뮬레이터 결과, 서버 정책 검증, 파일럿 관찰을 별도로 기록한다. 쓰기 지연이나 네트워크 실패를 재현하는 테스트에는 실제 실패 시점과 결과를 남긴다. [출범 계획서의 단계별 검증](project-kickoff.md#3-개발-단계와-전환-조건)을 기준으로 적용한다.
