# Me-mento 제품 기획 및 구현 명세

2026년 11월 24일 · iPad 첫 배포 및 정보처리기사 공유 파일럿

## 1. 제품 정의

**Me-mento는 같은 공부를 한 사람의 노트에서 놓친 내용을 발견하고, 가져온 노트에 자기 설명을 더해 다시 공부할 수 있는 iPad 암기노트 앱이다.**

자격증을 공부하다가 책이나 공유 PDF에서 시험에 나올 가능성이 작아 보이는 문제를 건너뛰고 나면, 다른 수험생이나 합격자도 그 내용을 건너뛰었는지 궁금해진다. 지금은 구글·블로그를 검색하거나 다른 사람에게 필기본이나 워드 파일을 받아 비교한다. 자료를 얻어도 같은 개념을 자기 이야기로 풀어 쓰거나, 손글씨로 보충하고 관련 개념을 연결하기는 번거롭다.

공개 노트는 다른 사람이 **무엇을 챙겼는지** 살펴보는 데 사용한다. 노트에 어떤 내용이 없다는 사실만으로 작성자가 그것을 의도적으로 건너뛰었다고 해석할 수 없다. 출제 경험은 작성자가 원할 때 소개나 개인 설명에 적을 수 있다. 별도 목차, 출제 여부 표시, 합격 인증은 첫 버전의 필수 입력에 포함하지 않는다.

첫 검증 대상은 정보처리기사 수험생이다. 취업을 준비하며 다른 기사 자격증을 공부하는 사람도 초기 대상에 해당한다. 제품 자체는 전공 수업, 어학, 독학 등 다른 주제에도 쓸 수 있게 한다. 필기·실기 중 어느 범위의 노트를 먼저 준비할지는 파일럿 운영에서 고른다.

이 문서에서 **확정**은 대화에서 합의한 제품 규칙, **구현 기본값**은 명세를 실행 가능하게 만들기 위해 이 문서가 제안하는 동작, **착수 시 결정**은 실기기 검증이나 운영 선택이 남은 사항을 뜻한다. 별도 표시 없는 핵심 기능과 사용 범위는 합의에 따른다.

## 2. 선택한 접근과 출시 범위

| 결정 | 검토한 접근 | 채택한 방식과 이유 |
|---|---|---|
| 개발 순서 | 필기만으로 먼저 공유 검증 / 필기와 마인드맵을 완성한 뒤 공유 | 필기·저장 → 마인드맵 → 공개·복사. 첫 공유 파일럿에서 두 탭이 함께 복사되고 편집되는 경험을 검증한다. |
| 마인드맵의 역할 | 개념별 부연 설명 / 노트 전체 요약 | 같은 노트의 별도 탭에서 전체 개념을 정리한다. 중심 주제와 하위 가지가 있는 트리로 시작한다. |
| 저장 | 개인 노트까지 클라우드 동기화 / 기기 내 작업과 서버 공개본 | iPad에 개인 노트를 저장한다. 서버에는 계정의 공개본과 공유 활동을 저장한다. 첫 배포에는 수동 전체 백업·복원을 제공한다. |
| 공유 | 전체 공개 / 링크 전용 / 받는 사람 지정 | 전체 공개와 비공개를 제공한다. 전체 공개 시 작성자가 복사 허용 또는 열람만 허용을 선택한다. |
| 탐색 | 자격증 필수 선택 / 자유 태그와 검색 | 주제에 관계없이 자유 태그를 쓸 수 있다. 기존 태그 자동완성으로 표현이 흩어지는 문제를 줄인다. |
| 인증 | 로그인 방식 하나 / Google과 Apple 제공 | 처음부터 Google과 Apple을 제공한다. 첫 사용 시 로그인하고 세션을 유지한다. 동일 계정에 두 방식을 연결하는 기능은 후순위다. |

**첫 배포 범위**에는 로그인과 홈, 기기 내 개인 노트, PDF·워드 가져오기, 손글씨와 메모, 마인드맵, 개인 태그와 제목 검색, 수동 전체 백업·복원, 공개·탐색·즐겨찾기·복사·재공개, 출처 표시, 신고 및 운영 조치, 작성자용 복사 횟수가 포함된다. 내부 필기 실험과 개인 노트 검증 단계에서는 아직 준비되지 않은 서버 기능을 요구하지 않는다.

## 3. 대표 사용자 여정

### 3.1 첫 사용과 노트 작성

1. 첫 실행에서 Google 또는 Apple로 로그인한다. 완료되면 홈이 열린다.
2. 사이드바의 `새 암기노트 만들기`를 눌러 시작 방식을 고른다.
3. `빈 필기 노트`는 필기 탭과 빈 페이지를 연다. `마인드맵`은 같은 구조의 노트를 만들고 마인드맵 탭을 연다. `PDF·워드 가져오기`는 파일을 골라 원래 페이지를 필기 탭에서 연다.
4. 제목을 바꾸고, 페이지를 추가·전환하며 필기하거나 메모를 보탠다. 마인드맵 탭에서는 노트 전체의 개념을 정리한다.
5. 홈이나 `내 노트`로 돌아간 뒤 다시 열면 이전 작업이 복원된다. 저장된 노트는 오프라인에서도 열고 편집할 수 있다.

### 3.2 공개 노트 발견과 복습

1. 홈의 최신 공개 노트나 `탐색`을 열고 제목·태그·소개로 검색한다. 태그로 결과를 좁힐 수 있다.
2. 카드에서 제목, 작성자 이름, 태그, 복사 권한을 확인한다. 읽기 전용 뷰어에서 필기와 마인드맵을 전환한다.
3. 나중에 다시 찾아볼 노트는 즐겨찾기한다. 실제로 공부할 `복사 가능` 노트는 `내 노트에 복사`한다.
4. 복사가 완료되면 보고 있던 탭이 새 개인 사본의 편집기로 열린다. 사본에는 두 탭과 페이지 전체가 들어 있다.
5. 원래 설명을 참고해 이야기, 손글씨, 메모를 보태거나 사본의 기존 내용을 자유롭게 고친다. 며칠 뒤 같은 iPad에서 다시 열어 복습한다.

### 3.3 공개, 업데이트, 재공개

1. 앱에서 직접 만든 노트 또는 재공개가 허용된 앱 내 사본에서 `공개`를 누른다.
2. **구현 기본값**으로 처음 공개하는 계정은 이 단계에서 공개 작성자 이름을 정한다. 제목, 태그, 선택 소개, 복사 권한, 현재 계정 이름, 공개 범위를 확인한다. 공개 시 필기·메모·마인드맵 전체가 올라간다는 점과 복사 허용 시 적용되는 조건을 표시한다.
3. 성공하면 그 시점의 노트가 로그인한 사용자에게 공개된다. 개인 노트를 계속 수정할 수 있다.
4. 후속 수정은 `공개본 업데이트`가 성공했을 때 새 공개 버전에 반영된다. 작성자는 `공유한 노트`에서 공개 상태, 복사 횟수, 운영 안내를 확인한다.
5. 다른 사람의 노트를 복사해 다시 공개하면 원본부터 직전 공개본까지의 출처가 이어진다. 수정본은 별도의 공개 노트다.

## 4. 화면과 이동

첨부된 iPad 화면 예시의 왼쪽 사이드바와 오른쪽 작업 영역을 홈의 기준으로 삼는다. 캘린더, 통계, 랭킹, 레벨은 각 기능을 구현한 뒤 추가할 수 있는 장기 화면 구성이다.

| 화면 | 첫 버전의 역할과 동작 |
|---|---|
| 로그인 | Google과 Apple 로그인 제공. 취소하거나 실패하면 해당 화면에서 다시 시도할 수 있다. |
| 홈 | 앱을 열면 도착한다. 최근 작업한 내 노트, 새 노트 시작, 최신 공개 노트 진입점을 제공한다. |
| 사이드바 | `새 암기노트 만들기`, `홈`, `탐색`, `내 노트`, `공유한 노트`, `즐겨찾기`로 이동한다. |
| 내 노트 | 최근 수정순, 제목 검색, 개인 태그 필터. 직접 작성, 가져오기, 앱 내 복사본을 함께 보여준다. |
| 편집기 | 제목, `필기 / 마인드맵` 탭, 현재 화면에 맞는 도구, 자동 저장 상태, 공개 진입점. 필기에는 페이지 목록과 페이지 추가가 있다. |
| 탐색 | 최신 공개 노트, 검색, 공개 태그 필터. 카드에는 제목, 작성자, 태그와 복사 권한을 표시한다. |
| 공개 노트 뷰어 | 읽기 전용 필기·마인드맵, 소개, 작성자, 출처, 즐겨찾기, 신고. 권한이 있는 경우 복사를 제공한다. |
| 공유한 노트 | 현재 계정이 공개한 노트, 공개 상태, 업데이트·비공개 전환, 복사 횟수, 파생본 안내를 보여준다. |
| 즐겨찾기 | 현재 계정이 저장한 공개 노트를 다시 여는 목록. 공개 중단 시 열람 불가를 알려준다. |
| 설정 | 로그인 방식과 로그아웃, 기기 내 노트가 남는다는 안내, 전체 백업과 복원. |

**구현 기본값**으로 새 노트 선택이나 파일 선택을 취소하면 빈 노트를 만들지 않는다. 최근 작업한 노트나 탐색 결과가 없으면 각각 새 노트 만들기와 필터 초기화처럼 지금 할 수 있는 행동을 보여준다. 홈에서 서버 연결이 실패해도 로컬 영역은 제공한다. 검색 결과 없음과 서버 조회 실패에는 서로 다른 메시지를 쓴다.

## 5. 개인 노트와 편집기

### 5.1 노트와 페이지

- 모든 노트는 제목, 순서가 있는 필기 페이지, 마인드맵을 가진다. 어느 탭에서 시작했든 두 탭을 전환한다.
- 노트와 페이지에는 제목이나 배열 위치가 바뀌어도 유지되는 식별자를 사용한다. 페이지 순서를 저장할 때는 해당 페이지의 필기와 메모를 함께 추적한다.
- 여러 노트와 페이지를 오갈 때 다른 페이지에 획이 저장되는 일이 없어야 한다. 탭 전환, 노트 닫기, 앱 재실행 후 각각의 상태가 복원된다.
- 개인 태그는 기기의 노트를 분류하는 데 쓴다. 공개 태그는 공개 과정에서 별도로 정한다. 폴더는 후순위다.
- **구현 기본값**으로 최근 수정 시간은 노트 내용을 변경했을 때 갱신한다. 단순 열람으로 최근 수정순을 바꾸지 않는다. 편집기는 마지막으로 열었던 탭과 필기 페이지를 기억한다.

### 5.2 손글씨, 메모, 제스처

| 입력 모드 | 필기와 지우기 | 화면 이동 |
|---|---|---|
| 손가락 필기 꺼짐, 기본 | Apple Pencil로 펜·지우개 사용 | 손가락으로 이동, 두 손가락으로 확대·축소 |
| 손가락 필기 켜짐 | Apple Pencil 또는 손가락 하나로 펜·지우개 사용 | 두 손가락으로 이동·확대·축소 |

- 사용자가 도구 막대에서 `손가락으로 필기`를 바꾼다. 마지막 선택을 재실행 후에도 유지한다.
- 우선 실기기에서 펜·지우개와 손바닥이 닿는 상황을 검증한다. 그 뒤 실행 취소·다시 실행, 여러 페이지, 형광펜, 줄노트, 텍스트 메모를 붙인다.
- 실행 취소·다시 실행은 **구현 기본값**으로 현재 편집 세션의 변경에 적용한다. 앱 재실행 후에는 마지막 저장 결과를 복원한다.
- iPad 네이티브 구현에서는 PencilKit의 `PKCanvasView.drawingPolicy`를 검증 후보로 사용한다. Pencil 전용과 손가락 허용을 전환하고, 스크롤·핀치와 획 입력의 충돌은 실제 iPad에서 확인한다. [Apple PencilKit](https://developer.apple.com/documentation/pencilkit/pkcanvasview/drawingpolicy)

### 5.3 자동 저장과 복원

- 저장 대상에는 펜·형광펜 획, 지운 결과, 텍스트 메모, 페이지 순서, 마인드맵, 노트 메타데이터가 포함된다.
- **구현 기본값**으로 완료된 획과 편집 변경을 편집 중에도 저장하고, 페이지·탭 전환 및 앱이 백그라운드로 갈 때 대기 중인 변경을 가능한 범위에서 저장한다.
- 저장을 완료했다는 표시는 디스크 기록 성공 이후에만 제공한다. 실패하면 편집 내용을 화면에 유지하고 재시도할 수 있게 한다. 이전에 저장된 정상 버전은 계속 열 수 있어야 한다.
- 프로세스를 강제 종료해도 마지막으로 저장 완료된 결과가 열려야 한다. 아직 끝나지 않은 획이나 저장에 실패한 변경은 복원을 보장할 수 없다.
- **구현 기본값**으로 페이지의 원본과 필기 좌표를 문서 기준으로 보관한다. 회전, 확대, 재열기 후에도 필기가 같은 위치에 놓여야 한다.

### 5.4 PDF·워드 가져오기

- 파일 앱에서 PDF·워드 파일을 고르면 사본을 기기 내 노트 자료로 보관한다. 가져온 원문 페이지 위에 손글씨와 텍스트 메모를 추가한다. 마인드맵 탭에서 문서 전체를 정리할 수 있다.
- 가져온 문서의 원래 문장을 편집하는 기능은 후순위다. 외부 자료가 있는 노트는 첫 버전에서 개인용이다. 전체 백업으로 보관·복원할 수 있다.
- **구현 기본값**으로 원본 파일이 파일 앱에서 옮겨지거나 사라져도 가져온 노트와 주석을 오프라인에서 다시 열 수 있어야 한다. 워드는 가져온 시점의 페이지 표현을 안정적으로 보관한다.
- 손상·암호화·지원하지 않는 문서나 가져오기 실패는 이유에 맞는 오류를 보여주고 기존 노트 목록을 보존한다. 임시 변환 결과만 남은 상태에서는 노트 생성을 완료하지 않는다.
- **착수 시 결정**으로 워드의 첫 지원 범위와 변환 방식을 정한다. `.docx`가 우선 검증 후보이며 레거시 `.doc`까지 지원하는지는 미정이다. 실제 한글 문서에서 줄바꿈, 표, 이미지, 페이지 나눔을 확인한 뒤 지원 범위를 명시한다. 오프라인 편집을 위해 최종 페이지와 첨부 자료는 기기 내에 보관한다.

### 5.5 마인드맵

- 같은 노트의 독립 탭으로 제공한다. 중심 주제 하나에서 하위 가지를 여러 깊이로 뻗을 수 있다.
- 중심 주제와 하위 노드 이름을 입력·변경하고, 하위 노드를 추가·이동·삭제한다. 노드 위치와 부모·자식 관계를 저장한다. 캔버스 이동과 확대·축소를 지원한다.
- **구현 기본값**으로 초기 중심 주제의 이름은 노트 제목으로 채울 수 있다. 이후 노드 이름은 독립적으로 편집한다. 노드 이동은 시각적 위치를 바꾸고 부모 관계를 유지한다. 관계를 다른 부모로 옮기는 동작은 이후 필요성을 확인한다.
- **구현 기본값**으로 중심 노드는 유지한다. 하위 가지를 지우면 포함된 자식 노드를 함께 지우며, 여러 노드가 지워질 때 범위를 확인할 수 있게 한다.
- 서로 다른 가지를 직접 잇기, 특정 필기 페이지나 문장으로 이동하기, 자동 마인드맵 생성, 상세 스타일 패널은 첫 범위 밖이다.
- 공개 뷰어에서는 저장된 위치와 관계를 그대로 표시한다. 복사한 노트에서는 두 탭이 편집 가능하다.

## 6. 계정, 저장 경계, 오프라인

| 데이터 | 저장 경계 | 계정 전환 또는 재설치 시 |
|---|---|---|
| 내 노트, 가져온 자료, 개인 태그, 편집 상태 | iPad | 같은 iPad에서 다른 계정으로 로그인해도 같다. 다른 기기에서는 수동 복원으로 가져온다. |
| 공개본, 공개 작성자 정보, 복사 횟수, 운영 안내 | 서버의 작성 계정 | 해당 계정으로 로그인하면 관리할 수 있다. 다른 계정으로 로그인해도 원래 계정의 공개본 관리 권한은 유지된다. |
| 즐겨찾기 | 서버의 이용 계정 | 같은 계정으로 로그인하면 다시 조회할 수 있다. |
| 사용자 전체 백업 파일 | 사용자가 선택한 파일 저장 위치 | 파일을 가져와 기기 내 노트 라이브러리를 복원한다. |

- 첫 사용은 온라인 로그인이 필요하다. 세션 복원에 성공하면 홈으로 진입한다. 돌아온 세션에서 네트워크가 일시적으로 끊겨도 기기 내 노트는 계속 열고 편집한다.
- **구현 기본값**으로 이 설치에서 로그인을 한 번 완료했고 이후 명시적으로 로그아웃하지 않았다면, 오프라인 재실행 때 서버 토큰이 만료되어도 기기 내 노트에 접근할 수 있다. 첫 실행이나 명시적 로그아웃 직후에는 로그인 화면을 연다. 서버 작업에는 유효한 온라인 인증이 필요하다. 재인증 요구나 서버 작업 실패로 로컬 변경이 사라지지 않으며, 온라인에서 계정 재인증이 필요하다는 응답을 받으면 안내한다.
- 로그아웃 직전에는 개인 노트가 이 iPad에 남고, 다른 계정으로 로그인하면 같은 노트를 볼 수 있다는 점을 알려준다.
- 같은 사람이 Google과 Apple을 각각 사용하면 첫 버전에서는 별개의 계정이다. 이메일 주소가 같다는 이유로 두 계정을 자동 병합하지 않는다.
- 공개 시 현재 로그인한 계정의 표시 이름을 보여준다. 공개 작성자 이름과 로그인 이메일을 분리한다.
- **구현 기본값**으로 한 계정은 같은 로컬 노트에 연결된 자신의 공개본만 업데이트할 수 있다. 다른 계정에서 동일한 로컬 노트를 공개하면 그 계정의 별도 공개 항목이 된다. 서버는 모든 관리 요청에서 현재 계정의 소유 여부를 검증한다.
- **착수 시 결정**으로 인증 백엔드, 자격 증명 보관 방식, 앱 배포에 필요한 계정 삭제 흐름과 공개 데이터의 잔존 정책을 확인한다. 기기 내 노트의 삭제·보관과 서버 계정 삭제는 사용자에게 각각 결과를 알려준다. [App Store 심사 지침](https://developer.apple.com/app-store/review/guidelines/)

## 7. 공개본, 권한, 복사와 출처

### 7.1 공개 상태와 권한

| 상태 | 탐색·열람 | 즐겨찾기 | 새 복사 |
|---|---|---|---|
| 비공개 | 개인 편집기에서 작성, 이전 공개본은 타인에게 제공하지 않음 | 이전 즐겨찾기에서 열람 불가 | 불가 |
| 전체 공개 · 복사 허용 | 로그인 사용자가 탐색하고 두 탭 열람 | 가능 | 가능 |
| 전체 공개 · 열람만 허용 | 로그인 사용자가 탐색하고 두 탭 열람 | 가능 | 불가 |
| 운영 조치로 내림 | 공개 상태와 무관하게 해당 공개본의 접근을 차단 | 기존 항목에서 열람 불가 | 불가 |

- 공개 시 작성자가 두 가지 권한 중 하나를 직접 고른다. 탐색 카드와 뷰어에서 권한을 확인할 수 있다.
- `복사 허용`은 앱 내 전체 복사, 자유 편집, 출처를 유지한 무료 재공개를 허용한다. 사본 판매는 허용하지 않는다. 앞서 제안된 전체 복사 기능의 유료화는 별도의 후순위 사업 검토 항목이다.
- 처음 공개한 노트에는 공개 식별자를 부여하고, 업데이트할 때 버전을 만든다. 서버의 탐색·즐겨찾기는 현재 열람 가능한 공개본을 연다. 출처 기록은 복사한 시점의 버전을 가리킨다.
- 업로드와 검증이 완료된 뒤에만 새 공개본을 노출한다. 실패하면 기존 공개본과 로컬 편집 상태를 유지하며 다시 시도할 수 있다.
- 공개 후 편집 내용은 `공개본 업데이트`가 성공하면 반영한다. **구현 기본값**으로 작성자는 `공유한 노트`에서 공개본의 복사 권한을 바꿀 수 있다. 권한 변경은 완료 시점부터 새 복사에 적용된다.
- 원본 공개를 중단하거나 `열람만 허용`으로 바꿔도 이전에 만들어진 사본과 공개 수정본은 유지한다. 링크 전용 공개와 특정 수신자 공유는 첫 범위 밖이다.

### 7.2 전체 복사

1. 로그인, 해당 버전의 공개 상태, 복사 권한을 서버에서 확인한다.
2. 제목, 페이지 순서와 필기·메모, 마인드맵 및 출처를 하나의 공개 버전으로 전달한다. 공개 전 작성자의 개인 태그나 비공개 작업본은 전달 대상에서 제외한다.
3. iPad에서 완성된 별도 노트로 저장한 뒤 편집기를 연다. 보고 있던 탭을 유지하고, **구현 기본값**으로 필기 뷰어에서 열어본 페이지도 대응 관계가 있으면 그대로 연다.
4. 저장이 실패하면 불완전한 노트를 목록에 남기지 않는다. **구현 기본값**으로 중복 탭과 재시도는 한 번의 복사 동작으로 처리한다. 사용자가 나중에 의도적으로 복사하면 독립 사본을 다시 만들 수 있다.
5. 이후 원본 업데이트는 기존 사본에 반영되지 않는다. 새 공개 버전을 가져오려면 다시 복사한다. 사본에서 원래 필기를 지우거나 마인드맵을 바꿔도 원본에 영향이 없다.

**구현 기본값**으로 목록·뷰어에 표시한 권한이 오래된 상태에서 복사를 누르면 서버의 현재 권한을 확인한다. 권한이 바뀌었거나 공개가 끝났다면 이유를 알려준다. 작성자의 복사 횟수는 중복 전송을 제외한 완료 복사 건수를 기준으로 표시한다. 성공 집계는 재시도에 대비해 동일 요청을 중복 반영하지 않도록 한다. 이용자의 실제 학습 여부는 별도로 검증한다.

### 7.3 출처와 후속 공개

- 예를 들어 `1번 원본 → 2번 수정본 → 3번 수정본`을 표시한다. 각 수정본은 직전에 복사한 공개 버전까지 기록한다.
- 사본을 편집하거나 전체 백업으로 복원해도 출처가 유지된다. 편집 화면에서 출처를 지우거나 편집할 수 없게 한다.
- **구현 기본값**으로 앱 내 복사 때 서버가 검증할 수 있는 출처와 재공개 권한 근거를 사본에 연결하고 백업에도 보존한다. 복사 허용 당시 얻은 사본은 같은 iPad에서 계정을 바꾸거나 다른 iPad에서 복원한 뒤에도 재공개할 수 있다. 재공개는 현재 계정의 별도 공개본을 만들며 상위 공개본의 관리 권한은 그대로 유지한다. 서버는 앱이 제출한 표시 이름이나 편집 가능한 로컬 문자열만으로 권한을 판단하지 않는다.
- 이전 출처가 비공개·삭제·운영 조치 상태라면 계보에는 해당 단계가 있었음을 표시하고 노트 열기는 막는다. UI에 표시할 이름 및 식별 정보의 최소 범위는 계정 삭제 정책과 함께 결정한다.
- `복사 허용` 당시 얻은 사본의 재공개 자격은 원본 작성자의 일반적인 권한 변경 이후에도 유지된다. 신고로 내려간 콘텐츠를 다시 올리는 문제는 운영 조치 규칙에 따른다.
- 외부 파일을 가져온 노트는 첫 버전에서 공개할 수 없다. **구현 기본값**으로 백업·복원 후에도 가져오기 여부와 공개 제한을 유지한다.

## 8. 신고와 운영

- 로그인한 사용자는 공개 뷰어에서 신고할 수 있다. 신고에는 대상 공개본과 버전, 사유, 선택 설명을 남긴다.
- 운영 권한을 가진 사용자가 신고 대상 버전을 검토하고 문제가 확인된 공개본의 추가 열람·복사를 차단할 수 있다. **구현 기본값**으로 조치의 대상, 사유, 처리 시각을 기록하고 서버에서 운영 권한이 없는 요청을 거부한다.
- 저작권 문제로 공개본을 내리면, **해당 버전에서 파생된 공개 수정본의 작성자**에게 깊이 제한 없이 `공유한 노트` 화면에서 검토 안내를 표시한다. 앱 내 안내부터 제공한다.
- 예를 들어 원본에 권한 없는 자료가 있고 2번 수정본에는 남아 있지만 3번 수정본에서는 빠졌다면, 운영자는 원본과 2번 수정본을 개별적으로 내릴 수 있다. 3번 작성자에게도 출처 검토 안내가 갈 수 있으며, 문제가 없는 3번 공개본은 유지한다.
- 작성자의 일반 비공개 전환과 운영 조치는 다른 사건이다. 운영 조치에도 이미 iPad에 보관된 사본은 유지된다. 서버에서는 문제가 남은 공개본을 별도로 다룬다.
- **구현 기본값**으로 조치한 버전과 파생본 안내를 각각 기록한다. 현재 공개 버전을 내리면 해당 공개 노트를 중단하고, 수정 후 재공개에는 운영 검토를 거친다. 신고가 이미 교체된 이전 버전만 대상으로 한다면 그 버전의 접근을 차단하고 해당 계보에 안내한다. 현재 버전은 문제가 남았다고 확인되면 별도 조치한다.
- **착수 시 결정**으로 운영자에게 필요한 화면, 신고 응답 절차, 저작권 문의·이의 제기 경로를 구체화한다. 푸시와 이메일 알림은 후순위다. App Store 공개 배포 전에 신고와 삭제 흐름뿐 아니라 부적절한 콘텐츠 대응, 악성 사용자 차단, 문의 연락처 등 적용되는 UGC 심사 요건을 검토하고 필요한 조치를 반영한다. [App Store 심사 지침 1.2](https://developer.apple.com/app-store/review/guidelines/#user-generated-content)

## 9. 전체 백업과 복원

첫 배포에 **이 iPad의 `내 노트` 전체를 파일 하나로 백업**하는 기능을 넣는다. 초기 필기 실험은 기기 내 자동 저장부터 검증한다.

- 백업에는 모든 개인 노트와 제목, 페이지 순서, 필기·메모, 마인드맵, 가져온 문서 자료, 개인 태그, 출처, 해당 노트의 공개 제한을 담는다. 편집 가능한 상태로 복원할 수 있어야 한다.
- **구현 기본값**으로 형식 버전을 두고, 복원 전에 구조와 참조를 검증한다. 로그인 토큰, 계정별 즐겨찾기, 서버의 공개 상태와 관리 권한은 백업 파일에서 복원하는 대상에 포함하지 않는다.
- 앱은 사용자가 고른 위치에 전체 파일을 저장한다. 쓰기 실패, 파일 형식 미지원, 저장 공간 부족, 취소에도 현재 라이브러리는 유지한다.
- 복원은 **현재 노트를 보존하고 추가한다**. 백업에만 있던 노트는 추가한다. 같은 노트의 내용이 같으면 **구현 기본값**으로 건너뛴다. 내용이 다르면 현재 노트를 두고 백업 쪽을 새 식별자의 `복원본`으로 추가한다.
- **구현 기본값**으로 복원 직전에 추가·건너뜀·별도 사본의 수를 보여준다. 동일 백업을 다시 가져오면 이전에 추가한 동일한 복원본을 중복 추가하지 않는다. 검증에 실패하거나 복원을 끝내지 못하면 일부만 정상 노트처럼 표시되는 상태를 피한다.
- 기기 내 노트의 한 권 단위 내보내기와 자동 클라우드 백업·동기화는 후순위다. 첫 버전의 백업은 마인드맵 CSV 교환 기능과 별개다.

## 10. 탐색, 태그, 즐겨찾기, 복사 횟수

- 공개 노트는 제목, 태그, 선택 소개로 검색한다. 손글씨 본문 OCR·검색은 기획 범위에서 제외한다. 노트 본문 분석으로 태그를 자동 지정하지 않는다.
- 작성자가 태그를 입력하면 같은 글자로 시작하는 기존 태그를 보여준다. 예를 들어 `정보처`를 입력하면 `정보처리기사`를 제안한다. 원하는 태그가 없으면 새로 만들 수 있다.
- **구현 기본값**으로 태그는 선택 입력이다. 동일 태그의 우발성 중복을 줄이기 위해 앞뒤 공백과 동일한 글자 표현을 정규화한다. `정처기`와 `정보처리기사`처럼 의미상 같은 표현은 자동 병합하지 않는다. 초기에 추천되는 기존 태그는 실제 태그 입력을 기준으로 한다.
- 탐색과 홈의 공개 노트는 최신 공개순을 기본으로 삼는다. **구현 기본값**으로 공개본 업데이트 후에도 최초 공개 시각을 유지해 같은 노트가 계속 최신 목록의 맨 위로 올라오는 일을 방지한다.
- 즐겨찾기는 해당 공개 노트의 현재 상태를 다시 확인하는 기능이다. 오프라인 편집 용도로 사용하려면 복사가 완료되어야 한다. 즐겨찾기 추가·해제는 계정별이며, 동일 노트를 다시 추가하는 요청에도 항목이 하나만 남는다.
- 복사 횟수는 해당 노트의 작성자가 `공유한 노트`에서 확인한다. 첫 배포의 공개 카드 정렬에는 복사 횟수를 사용하지 않는다.

## 11. 구현에 필요한 개념과 계약

아래 이름은 구현 전달용 개념이며 실제 타입과 테이블 이름은 구현자가 정한다.

| 개념 | 책임 |
|---|---|
| 기기 내 노트 | 제목, 개인 태그, 원본 종류, 페이지와 맵, 최근 작업 위치, 사본 출처를 가진다. 계정 전환으로 소유자를 바꾸는 서버 레코드가 생기지 않는다. |
| 필기 페이지 | 안정적인 ID, 순서, 배경 또는 문서 페이지, 손글씨, 텍스트 메모를 가진다. |
| 마인드맵 | 루트와 하위 노드, 부모 관계, 각 노드의 이름·좌표를 가진다. 잘못된 부모 참조와 순환을 방지한다. |
| 공개 노트 | 서버 식별자, 작성 계정, 가시성, 복사 권한, 현재 공개 버전, 운영 상태를 가진다. |
| 공개 버전 | 공개 시점의 문서 내용과 공개 메타데이터를 일관된 묶음으로 제공한다. 공개 상태 변경 후에도 출처 판단에 필요한 버전 관계를 보존한다. |
| 출처 | 직접 복사한 공개 버전과 상위 계보, 그 시점의 복사·무료 재공개 권한 근거를 나타낸다. 복사를 수행한 계정과 현재 공개하는 계정이 다른 경우에도 기기 내 사본의 출처와 재공개 허용 근거를 유지한다. |
| 서버 활동 | 즐겨찾기, 완료 복사 집계, 신고, 운영 조치, 파생본 작성자 안내를 관리한다. |
| 백업 | 형식 버전이 있는 기기 라이브러리와 첨부 자료의 이동 단위다. |

**구현 기본값**으로 각 작업의 완료 경계를 다음과 같이 정의한다. 기기와 서버에 걸친 작업은 재시도해도 결과가 중복되지 않도록 처리한다.

- 개인 노트 편집 → 디스크 저장 완료 → 해당 변경 복원 가능
- 공개 요청 → 내용과 권한 검증 → 공개 버전 활성화 → 새 버전 열람 가능
- 복사 요청 → 현재 권한 확인 → 문서 묶음 수신 → 기기 저장 완료 → 편집기 진입
- 백업 복원 요청 → 파일 검증 및 충돌 파악 → 라이브러리 추가 완료 → 복원 결과 표시
- 운영 내림 → 해당 공개본 접근 차단 → 검토 안내 대상을 버전 계보로 찾아 기록

서버는 공개 목록·상세·복사·운영 관리의 인증과 권한을 각각 확인한다. 비공개 전환과 운영 내림은 검색 결과와 직접 접근 경로에 함께 반영한다. 화면 버튼의 표시 여부를 서버 권한 검증과 함께 사용한다. 사용자가 같은 요청을 재시도하거나 네트워크 오류 직후 돌아와도 완료 상태를 다시 확인할 수 있어야 한다.

## 12. 단계별 개발과 완료 기준

| 단계 | 범위 | 완료 기준 |
|---|---|---|
| 1. 실기기 필기 실험 | iPad 한 화면, Pencil과 손가락 모드, 펜·지우개, 이동·확대 | 실제 iPad에서 손바닥을 올린 Pencil 필기와 두 손가락 이동 시 원치 않는 획이 없고, 각 모드에서 쓰고 지울 수 있다. |
| 2. 한 페이지 저장 | 자동 저장, 취소·다시 실행, 재실행, 저장 실패 처리 | 앱을 닫고 다시 열면 필기와 지운 결과가 복원된다. 저장 실패 후 기존 저장본과 현재 작업을 보존하며 재시도할 수 있다. |
| 3. 개인 노트 | 홈과 목록, 제목·개인 태그, 페이지, 형광펜·줄노트, PDF·워드 가져오기 | 여러 노트와 페이지의 필기가 섞이지 않는다. 가져온 문서 위에 필기한 뒤 오프라인에서 다시 열 수 있다. |
| 4. 마인드맵 | 같은 노트의 두 탭, 트리 편집과 저장 | 탭 전환과 앱 재실행 후 위치, 관계, 필기 상태가 각각 유지된다. |
| 5. 공유 파일럿 | 로그인과 세션, 공개 검색·권한, 복사·즐겨찾기·출처, 신고·운영 안내 | 다른 계정이 공개 노트를 찾아 복사하고, 보고 있던 탭에서 두 탭을 포함한 사본을 편집한다. 원본과 사본이 서로의 변경에 영향을 주지 않는다. |
| 배포 준비 | 전체 백업·복원, 로그인과 운영 정책 점검, 기기 검증 | 백업으로 편집 가능한 노트를 복원하고 현재 라이브러리를 보존한다. 기능 검증과 파일럿 검증을 각각 완료한다. |

Google·Apple 인증, 서버 운영, 워드 변환 경로는 후속 단계의 의존성으로 미리 조사할 수 있다. 실제 개발 시점에는 iPad용 빌드·서명 환경과 Apple Pencil을 쓸 수 있는 실기기를 확보한다. 클라우드에서 가능한 문서·서버·데이터 검증과 iPad 입력 검증을 별도로 기록한다.

파일럿 시작 전에 공유 권한이 있는 정보처리기사 노트를 소량 준비한다. 필기 중심 노트와 마인드맵이 있는 노트가 둘 다 있으면 같은 흐름에서 두 탭을 확인할 수 있다. 이는 운영 준비 사항이다.

기능 테스트를 통과한 뒤 수험생이 실제로 놓친 내용을 발견하는지, 전체 복사를 하는지, 사본에 자기 설명을 더하는지, 이후 사본을 다시 열어보는지 확인한다. 조회나 복사 횟수만으로 학습에 사용됐다고 해석하지 않는다. 첫 파일럿의 참가자 수와 판정 기준은 운영 준비에서 정한다. 학습 내용을 수집하지 않고도 이러한 작업 흐름을 점검할 수 있는 형태를 우선한다.
